# 응용

## AI 기반 서버 장애 분석 Agent PoC

### 목표

장애 발생 시 엔지니어가 여러 시스템을 직접 돌아다니며 증거를 수집하는 시간을 줄이고, Agent가 **증거 수집 → 원인 후보 축소 → 근거 정리**까지 자동화한다.

### 흐름

```text
장애 발생
→ 로그 조회
→ APM / Metric 조회
→ 최근 배포 이력 확인
→ 관련 코드 변경 확인
→ Runbook / 과거 장애 RAG 검색
→ 원인 후보 생성
→ 추가 Tool 조회
→ 원인 / 근거 / 대응방안 정리
```

### 적용 개념

- **RAG**: Runbook, 과거 장애 사례, 시스템 문서 검색
- **Tool Calling**: 로그, Metric, 배포 이력, Git 조회
- **ReAct**: 조사 → 관찰 → 추가 조사 반복
- **Context Engineering**: 대용량 로그를 필요한 구간만 선별/요약
- **Agent**: 어떤 Tool을 언제 쓸지 판단

### 초기 PoC 원칙

처음에는 **Read-only**로 구성한다.

AI가 분석까지만 수행하고 실제 재시작, Rollback, 설정 변경은 사람이 승인한다.
